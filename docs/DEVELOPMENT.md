# 開発・テスト

Node.js 20以降が必要です。ビルドとユニットテストに外部パッケージは不要です。

```sh
npm run build
npm test
npm run check:build
```

`extension/content.js` は生成物です。直接編集せず、`src/` を変更してからビルドしてください。生成済みファイルを同梱しているので、拡張機能を利用するだけならNode.jsは不要です。

## 構造

- `src/core/timing.mjs`：純粋なタイミング補間関数。単位はミリ秒、位置は0〜1。
- `src/core/lrc.mjs`：LRC書き出しと補正時刻の逆算。入力の歌詞・補正データを変更しません。
- `src/content/lyrics-panel.js`：歌詞候補、編集、ローカル歌詞作成、メニュー、診断表示。
- `src/content/timing-offset.js`：曲別の補正ポイント管理と操作画面。
- `src/content/auto-open.js`：歌詞タブ判定、自動表示、タブ操作。
- `src/content/providers.js`：外部提供元への問い合わせ。
- `src/content/lyrics-storage.js`：保存した歌詞、編集、キャッシュ、表示への適用。
- `src/content/track-search.js` / `tracking.js`：曲切り替え時の検索と同期追跡。
- `src/content-order.json`：ビルドする機能別ソースの順番。
- `scripts/build.cjs`：依存パッケージなしのビルド。構文を検査し、単一の隔離スコープ内へ結合します。
- `tests/`：Node標準テストランナーで実行する、コア計算・送信制限・保存競合・生成物一致のテスト。

コアは直接importできるES Modulesです。UI側は既存動作を維持するため、共有状態を持つビルド用ソースとして機能別に分割しています。UIファイル間の依存関係まで完全に独立化した構成ではありません。次の段階で必要に応じて状態の受け渡しを明示的にしていけます。

コアモジュールはビルド時に関数のexport宣言を外して組み込みます。任意のESM構文を処理する汎用バンドラーではありません。新しいimportやクラスを追加する場合はビルド側も対応させてください。ビルドの構文チェックと生成物一致テストが不整合を検出します。

## テスト対象と制限

タイミングの境界・補間・±20秒、LRC丸め、行削除・編集、補正反映の逆算、ヘッダーの許可リスト、送信元とホスト制限、保存処理の直列化などを検証します。合成データだけを使い、ネットワーク送信や利用者の保存データの削除は行いません。

ライブのYouTube Musicと外部APIの変更はユニットテストだけでは確認できません。変更後はテスト用プロファイルで「歌詞→関連→歌詞」の往復、候補固定、ローカル歌詞、LRC保存、拡張更新後の再読み込み案内も確認してください。
